# QA랩 1차 MVP 요구 반영표

대상 지시: `ORDER_USER_DIRECTIVE_20261120_RAW.txt`의 2. QA랩. 원문은 별도 보관하고 이 문서는 구현과 검증 상태만 기록한다.

## 인벤토리와 보존

- 기존 카탈로그: 97개 화면군, 496개 고유 상태, 변형을 포함한 498행을 보존했다.
- 추가: 컴포넌트 라이브러리 30상태(23개 원본 자산별 검토, 2개 3D 모션 변형 검토, 5개 보드), 수익 배분 1상태, 이메일 양식 3상태, 매장 구매 3상태, 기존 성과 화면군에 사업장·공동구매 매출 2상태. 신규 합계 4개 화면군·39상태다.
- 현재 합계: 101개 화면군, 535개 고유 상태, 537행.
- 기존 상태 보완: 납품 요청 6상태, 회원탈퇴 확인 1상태, 관리자/농장 출고 상세 각 1상태. 이전 본문·런타임·해시는 기존 생성 파일에서 계속 조회된다.
- 기존 댓글 원문, 위치 핀, 사용자 통과 판정, 답글, 변경 이력은 변경하지 않았다. 신규 자산도 기존 QA 저장 API의 별도 화면/상태/폭/해시로 코멘트와 해결 상태를 관리한다.

## 요구별 상태

여기서 **구현**은 지정한 범위의 동작이 소스와 검사로 확인됐다는 뜻이다. **QA 흐름**은 격리된 디자인 검토 화면에서 작동하며 운영 데이터를 생성하지 않는다. **기존 재사용**은 기존 상태를 복제하지 않고 1차 MVP 메뉴에 배치했다는 뜻이다. 실제 브라우저 검사는 CI 실행 결과를 별도 기록해야 한다.

## 첫 매장 매출을 위해 추가로 확정할 업무

1. **주문과 가격 고정:** 주문 시점의 승인 단가·포장·배송비·최소 주문·유효기간을 주문에 고정하고, 견적 만료/가격 변경 시 재확인해야 한다.
2. **결제와 출고 대조:** 카드 승인과 현금 입금을 같은 주문 번호로 대조한다. 중복 입금, 일부 입금, 결제 후 취소, 확인 취소를 운영자가 처리할 경로가 필요하다.
3. **농장 출고 예외:** 품절·생산 부족·출고 마감·배송 불가 지역·일정 변경·분할 납품과 파손/반품의 처리를 정해야 한다.
4. **증빙 발행:** 견적서·영수증·명세서 번호, 발행 대상, 재발행·취소·정정 기록과 실제 결제 금액을 연결해야 한다.
5. **수익 배분 마감:** 수수료/포장/운임/반품을 어떤 순서로 차감하는지, 소수점 처리, 지급 보류, 마감 뒤 수정, 최초 기여자 코드 충돌 규칙을 정해야 한다.
6. **운영 담당과 고객 안내:** 미입금/승인 대기/출고 지연 항목의 담당자를 지정하고 고객 연락·상담 이력을 주문과 연결해야 한다.

## 검증과 게시 경계

- `tests/r3-qa-mvp.test.mjs`: 메뉴 기본 분류/단일 소속, 계정별 저장·동시 수정 충돌·이력, 이름/이동 UI, 실제 자산 사용처, 이전 아티팩트 보존, 카드 플립, 탈퇴 가드, 카드/현금 동일 금액, 수익 배분, BLOUB 조합, 송장 입력, 3D 원본 불변·모션 제어·재생 중 모션 감소 반영. 배송·구매·배분은 직접 버튼 클릭/Enter와 필수값 검증을 함께 검사한다. 매출 두 상태의 독립 합계, 월/대상/주문번호 필터, 전액 환불·미입금 취소, 역전 기간·빈 검색, 원본 성과 5상태의 본문·해시 보존을 검사한다.
- `tests/r3-qa-mvp-bundle.test.mjs`: Wrangler의 `keepNames`와 minify 이후에도 모든 추가/보완 아티팩트와 publication receipt의 해시가 같아야 한다.
- 기존 `r3-qa-ui`, `r3-qa-publication`, `r3-qa-interactions` 회귀 검사를 유지했다.
